## 1. 阶段 0：环境核查与文档基线（已完成）

**任务**
- 检查工作区、运行时、包管理器、开发者工具、CloudBase、官方数据源可达性。
- 建立 `docs/environment-report.md`、`implementation-plan.md`、`decisions.md`、`compliance-checklist.md`、`data-source-plan.md`。

**验收**：五份文档存在，且不含虚构的官方批准结论；环境限制对应到具体技术决策。

## 2. 阶段 1：工程骨架与单用户身份（本轮完成）

**任务**
1. 原生小程序工程：`app.json`（4 个 tab：首页/开奖/我的号码/AI 助手）、全局主题、空状态组件、请求封装。
2. `shared/` 共享层：彩种常量、号码校验、统一的 `{success, code, message, data, requestId}` 返回结构、访问控制纯函数。
3. 云函数 `authCheck`：读 `wxContext.OPENID` → 比对 `app_config.ownerWhitelist`（缺失时回退环境变量 `OWNER_OPENID`）→ 返回准入结果。
4. 前端启动鉴权：`app.js` 调 `authCheck`，未授权跳 `blocked` 页并阻断后续请求。
5. 单元测试：号码校验（主方案 16.1 全表）、访问控制、返回结构。

**验收标准**
- [x] `node --test` 全绿（结果见 `docs/phase-1-report.md`）。
- [x] 未授权时前端进入拒绝页，且 `services/api.js` 在未授权态拒绝发起业务调用。
- [x] 前端代码与仓库中不含任何 API Key。
- [ ] 微信开发者工具可编译运行（**待 U1**，本轮无法验证）。

**已知缺口**：真机/模拟器未验证；`app_config` 集合尚未创建（云环境未开通），当前鉴权回退到环境变量。

## 3. 阶段 2：开奖数据（下一步）

**任务**
1. `draw_records` / `draw_rules` / `sync_logs` 集合与索引说明；`game+issue` 唯一。
2. 适配器接口 `fetchLatest(game)` / `fetchByIssue(game, issue)`；首版实现：官方往期公告列表页 HTML 解析（`www.cwl.gov.cn/ygkj/wqkjgg/{ssq|kl8}/`）。
3. 解析 → 规范化（升序整数数组）→ 校验（数量/范围/去重/期号单调/日期合法）→ `rawHash` + `parserVersion` → 状态机 `pending → parsed → verified|conflict`。
4. CSV/JSON 手动导入兜底（含 `sourceType=manual_official_import` 与核验人字段）。
5. 页面：开奖列表（彩种/年份/期号/分页）、开奖详情（号码、奖级、来源 URL、抓取时间、核验状态）。
6. 同步日志页/接口；失败时保留旧数据并显示上次成功时间。

**验收**：主方案 16.5 全部用例；用 1 个真实期次 + 1 组构造异常数据端到端跑通；重复同步不重复插入；冲突不覆盖。

**风险点**：页面结构变更 → 解析器版本化 + 单测样本快照；CloudBase 出网可能受限 → 手动导入为第一兜底。

## 4. 阶段 3：个人号码管理

**任务**
1. 双色球选择面板（01–33 选 6、01–16 选 1，点击/输入/清空/随机/替换）。
2. 快乐8选十面板（01–80 选 10）。
3. 记录状态机：`draft → confirmed → checked`，旁路 `void`；`confirmed` 后号码字段冻结，仅可改备注/金额/倍数。
4. 我的号码列表（按彩种/期号/状态筛选）、详情、编辑、复制、作废、删除（二次确认）。
5. 导出 CSV/JSON（本人记录）。

**验收**：主方案 16.4 候选/购买隔离用例；非法号码在前后端双重拒绝；连续点击不产生重复记录（幂等 key）。

## 5. 阶段 4：判奖引擎

**任务**
1. `shared/rules/` 规则版本：`ssq_2026_02_01`（自 2026014）、`kl8_2025_12_30`（自 2025350）；旧版本未取得权威资料前声明"不支持自动核对"，走人工。
2. 双色球：六奖级 + 福运奖（`specialRuleStatus` 三态：active/inactive/unknown → unknown 必须 `pending_manual_review`）。
3. 快乐8选十：10(浮动)/9/8/7/6/5/0(2元)，1–4 不中奖；按期号选版本，禁止新规则回算旧期。
4. 奖金来源：一等奖/二等奖、快乐8 10 中 10 一律读当期公告；缺失返回"奖金待官方公告"，不估算。
5. `checkTickets` 云函数：仅 `confirmed` 记录 + 仅 `verified` 开奖；幂等键 `ticketId+drawRecordId+ruleVersion+drawHash`；支持重算并保留旧版本。

**验收**：主方案 16.2、16.3 全表用例 + 概率公式自检（`C(33,6)*16=17,721,088`）；返回结构符合 8.4。

## 6. 阶段 5：DeepSeek AI 助手

**任务**
1. 服务端配置：`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL=deepseek-flash`（可改，不写死）。
2. 工具白名单 7+1 个（`get_latest_draw`/`get_draws`/`get_my_tickets`/`get_my_ticket_stats`/`get_number_stats`/`get_ticket_check`/`get_rule_info`，`generate_candidates` 受开关控制）；服务端强制附加 owner OpenID，参数白名单校验。
3. 编排：最多 3 轮工具调用、输入长度上限、超时、Token 记录；失败降级为可读提示。
4. 会话与消息存储；输出过滤（禁止预测类表述、禁止编造数据）。
5. 前端 AI 页 + 免责说明 + 可关闭。

**验收**：主方案 16.6 全部用例；密钥扫描（前端包内 grep `sk-` 无命中）；API 故障不影响开奖浏览与本地判奖。

## 7. 阶段 6：候选组合（合规闸门）

**前置**：U4 取得平台明确许可；否则代码仅在开发环境可用，生产配置保持关闭。

> 2026-11-05 更新：主线迁到静态站后无平台可审批，改为"本人知情确认"闸门（D23）。
> 交付与偏离项见 `docs/phase-6-report.md` 第 6 节。

**任务**：`random`/`balanced`/`preference` 三策略；默认 3 组且组间不重复；保存 `targetIssue`、`algorithmVersion`、`parameterSnapshot`、`randomSeed`、`complianceState`；导入仅生成 `draft`；服务端每次都校验 `candidateGenerationEnabled && wxComplianceStatus === 'approved'`。

**验收**：主方案 16.4；关闭开关时前端入口隐藏且云函数返回 `FEATURE_DISABLED`。
