# 选号分析模型（拥挤度）

> 版本：`crowd@1.0.0`｜代码：`shared/domain/analysis.js`
> 目的：把"分析选号"这件事讲清楚——它能改什么、不能改什么、依据是什么。

## 1. 一句话结论

**选号分析不能提高中奖概率，永远不能。**
它能做的是：**降低"万一中了浮动奖，被很多人平分"的概率**。

双色球一等奖、二等奖，快乐8 选十中十是**浮动奖，按中奖注数均分**；
三等奖及以下（3000 / 200 / 10 / 5 元等）是固定奖金，不受影响。

所以本项目的"分析"不是预测，是**避拥挤**。

## 2. 研究依据

| 来源 | 结论 | 用在哪 |
|---|---|---|
| Cook & Clotfelter (1993)，"conscious selection" | 玩家系统性用生日/日期选号，1–31 被超额选择 | 生日区权重 |
| Farrell, Hartley, Lanot & Walker (2000)，英国 | 7 是最热门号，被选频率比最冷的 46 高约 25% | 7 的权重 |
| Cox 等 (1998)，南安普顿大学，JRSS-A | 冷门组合长期回报约 95 便士/英镑，随机约 45 便士——**翻倍但仍 <1** | 说明"只能改善、不能盈利" |
| Baker & McHale (2009)，JRSS-A | 玩家偏爱"看起来被设计过"的票：连号、等差、等间距 | 连号/等差/同尾惩罚 |
| 案例：1995 英国 | 133 人平分 1600 万英镑头奖（号码集中在卡中间列） | 说明均分风险真实存在 |
| 案例：2008 加拿大 | 开出 40-41-42-43-44-45，二等奖 239 注 | 连号被大量投注 |
| 心理学调查 | 约 30% 玩家用生日/纪念日选号 | 生日区权重的量级 |

**必须说明的限制**：中国福彩不公布每注号码的投注分布，所以本模型是**基于上述公开研究的推定**，
不是实测投注人数。界面上不能写成"多少人买了这组号"，只能说"预计拥挤度"。

## 3. 权重表

单位是"人群偏好分"，正数=更像大众会选，负数=大众回避。
集中定义在 `shared/domain/analysis.js` 的 `WEIGHTS`，改权重必须升版本号并补测试。

| 因子 | 分值 | 说明 |
|---|---|---|
| 生日区超出期望 | +1.6 / 个 | ≤31 的号码比随机期望多几个 |
| 日/月重叠超出期望 | +0.5 / 个 | ≤12 的号码（既是日期又是月份） |
| 6 / 8 / 9 | +0.5 / 个 | 中文吉利数 |
| 4 | −0.5 / 个 | 中文忌讳，反而少人选（推定） |
| 7 | +0.6 / 个 | 多国最热号 |
| 整注都在 1–31 | +3.0 | 最拥挤的区域 |
| 连号 | +0.8 / 对（最多 2 对） | "看起来有规律" |
| 等差（≥4 项，或三连号） | +2.0 | 见下节校准说明 |
| 同尾号 | +0.4 / 对（最多 2 对） | 视觉规律 |
| 与上期重号 | +1.0 / 个（最多 3 个） | 近因偏差 |
| 和值落在最常见区间 | +0.5 | "看起来最正常"的号，也最挤 |
| 全奇 / 全偶 | −0.8 | 人很少这么选 |
| 蓝球 ≤12 | +0.5 | 日期可达 |
| 蓝球 13–16 | −0.3 | 日期不可达 |
| 蓝球 7 / 8 | +0.4 | 热门 |

**换算**：`指数 = clamp(50 + 总分 × 5, 0, 100)`。越低越冷门。

| 指数 | 等级 |
|---|---|
| ≤25 | 低 |
| 26–42 | 中低 |
| 43–58 | 中 |
| 59–72 | 中高 |
| >72 | 高 |

参考值：`1 2 3 4 5 6 + 7` ≈ 100（高）；`3 8 12 21 26 30 + 8` ≈ 89（高）；
`4 17 25 29 32 33 + 16` ≈ 34（中低）。

## 4. 校准踩过的三个坑（写下来免得再犯）

1. **按"号码绝对个数"算生日区，指数失去区分度。**
   双色球 33 个号里只有 32、33 在日期之外，几乎每注都有 5–6 个 ≤31，
   于是所有组合都被判"高"。改成"超出随机期望的个数"后才区分得开。

2. **等差数列用"长度 ≥3"会把普通组合误伤。**
   随手 6 个号里出现 3 项等差太常见（如 5、11、17）。改成**长度 ≥4，或三连号**才算"设计感"。

3. **快乐8 沿用双色球的连号/同尾阈值，会把合法组合几乎全部误杀。**
   选 10 个号时，同尾对数期望就有 4.5 对。阈值必须随号码个数放大
   （连号 >2 对、同尾 >2 对、等差 ≥5 项才拒）。

## 5. 与选号策略的关系

新增第 4 种策略 `analyzed`（界面上叫「分析选号」）：

```
采 600 组候选
  → 丢掉不满足硬约束的（和值区间、奇偶个数、避开模式、含冷号）
  → 丢掉与前几注重合 >3 个的（避免把钱押在一个形状上）
  → 目标函数：拥挤度 + |和值 − 中心值| × 0.25
  → 取最小值
```

**为什么要加"和值偏离惩罚"**：只追求最冷门，每注都会挤到"全大号"那一角，
结构就崩了。惩罚项就是"两者兼顾"的具体含义——界面上会同时显示
平均拥挤指数、和值范围、几注含 32/33、几注带连号，把代价摊开给你看。

## 5.5 统计窗口与样本量（必须如实说）

分析选号的「统计窗口」可选近 30 / 50 / 100 / 200 / 300 期，只影响两件事：**冷号**与**上期重号**。

- 窗口越大，冷号越少（覆盖的历史更全），"避开上期重号"的参照也越远。
- 批次里会记录 `window`、`sampleSize`（实际用了几期）、`dataSufficient`。
- 若本地只有 10 期却选"近 100 期"，`sampleSize` 记 10、`dataSufficient` 为 false，
  界面会写"样本不足，冷号与重号判断会偏粗"，AI 也必须照实说。

这不是礼貌问题：**说"近 30 期"却只用了 10 期，就是在虚报依据。**

> 数据来源是仓库里的 `web/data/draws/*.json`。
> 双色球支持 pageNo 翻页、快乐8 必须用 issueStart/issueEnd 区间，
> 所以补历史用 `npm run sync:history`（各 300 期）。
> 日常更新用 `npm run publish:data`，或无人工干预的计划任务 `npm run task:install`。

## 5.6 AI 到底参与了多少（说清楚）

选号这条链路上，**号码永远由代码生成**，AI 不产出号码。具体分工：

| 环节 | 谁做 | 说明 |
|---|---|---|
| 采样 600 组、过滤硬约束 | 代码 | 和值/奇偶/避开模式/冷号 |
| 拥挤度打分 | 代码 | `crowd@1.0.0` 权重表，确定性 |
| 目标函数取最优 | 代码 | 拥挤度 + 和值偏离惩罚 |
| 选择策略与权重 | 你（页面）或 AI（对话） | AI 把你的自然语言翻成 `analysis` 参数 |
| 解释结果 | 你（页面模板）或 AI | AI 只能引用工具返回值，不许改号 |

所以：
- 在「选号」页点生成 —— **完全不经过 AI**，不花 token、不联网。
- 在「AI」页说"给三注，别要生日号，带个冷门号" —— AI 只负责把那句话翻成
  `strategy=analyzed` + `analysis.avoidRepeat/includeCold/...`，号码仍由代码生成。

为什么不让 AI 直接吐号码：模型输出不可复现、无法复盘，而且它会"顺手"编造规律。
让代码生成 + AI 解释，能保证同种子同结果。

## 6. 冷号怎么用（重要）

`coldNumbers()` 统计近 30 期一次都没出现的号码。

- **用途**：当作"大众很少选的号"来降低拥挤度（大家爱追热号）。
- **不是**："该回补了"。遗漏 40 期不开在历史上很常见，冷号下一期出现的概率和热号完全一样。
- 所以界面上写的是"每注至少带几个冷号"，下面紧跟一句"不代表它该开了"。

## 7. 明确不做

- 不预测下期号码，不给"必出/回补/走势反转"这类结论
- 不承诺收益（Cox 那项研究里最冷门的组合也只有 95 便士/英镑）
- 不根据历史频次加权选号（那是把随机包装成推断）
- 不虚构"有多少人买了这组号"（没有这种数据）

## 8. 如果要做得更准

唯一有实质意义的改进是拿到**真实投注分布**——但福彩不公开。
次优方案是用公开的中奖注数反推（某期某奖级中奖注数异常高 → 那组号码很挤），
这需要长期累积数据，且只能做"事后校准"，不能做"事前预测"。
当前不做。
