## 4. 关键实现说明

1. **金额不猜**：草稿 `actualCost` 恒为 `null`；确认购买必须填金额（赠票填 0）。双色球单价已核对（2 元/注）才给占位建议，快乐8 单价未核对 → 只提示"按实际支付填写"，不给数字（`decisions.md` D15）。
2. **期号不推算**：录入页必须手填 7 位期号，页面明写"系统不会用上期 + 1 推算"。
3. **改号 = 作废重建**：`confirmed` 记录改号被服务端拒绝，提示先作废再新建，保留操作痕迹。
4. **幂等键在页面实例内生成一次**：连点保存不会产生重复草稿（服务层测试覆盖）。
5. **页面无"自动勾选全部"之类捷径**：随机一注是显式按钮，且不改变"仍需确认购买"的状态。

## 6. 已知问题

1. 选号网格未做虚拟滚动：快乐8 80 个号码一次性渲染，低端机可能略有卡顿（可接受，后续按需优化）。
2. `ticket-detail` 的购买日期只精确到日（默认当天 12:00），未支持具体时刻。
3. `queryTickets` 列表每次请求会额外执行 3 次 `count()`，属可接受开销；数据量大后可改为缓存或聚合。
4. 号码重复（同 game+issue+同组合）暂不拦截也不提示——用户可能真的买了两张相同号码，强行拦截反而错误。
