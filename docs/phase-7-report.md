## 2. 统计口径（不变量）

1. **只统计 `confirmed`**：草稿与已作废不进投入、不进中奖、不进命中分布。
2. **奖金只来自核对结果**：`pending_manual_review` 与待公告金额不计入合计，页面显示"另有 N 条待处理"。
3. **未填金额的票单独提示**：`missingCost > 0` 时说明"投入金额偏低"，不按 2 元/注补齐。
4. **开奖结构只算已核验数据**：本地同步了几期就算几期，样本不足直接在页面上说"请求 30 期，本地只有 10 期"。
5. **不产生倾向性结论**：所有统计块都带一句"这是历史描述性统计，不预示下一期"。

## 3. 统计页新增了什么

- 窗口切换：近 30 / 50 / 100 期（取本地已有数据，不额外请求）。
- 号码频次三栏：出现最多 5 个 / 出现最少 5 个 / 遗漏最长 5 个，均带次数与遗漏期数。
- 和值分布：6 个动态区间（按实际 min–max 切分），附最小/平均/中位/最大。
- 奇偶结构：`0 奇 6 偶` … `6 奇 0 偶` 的期数分布。
- 分区占比：双色球三区、快乐8 四区，带平均每期个数与断区次数（并说明断区不是"该回补"）。
- 连号：含连号的期数占比与平均对数。
- 我的命中分布：双色球按红球命中数分桶并单列蓝球命中注数；快乐8 按 0–10 分桶。

图表是**纯 CSS 条形**，没有引入任何图表库——项目红线是零运行时依赖。

## 4. 恢复与清空

### 4.1 恢复：先预览，再写入

原来选文件就直接写库，风险是"覆盖了什么完全不知道"。现在改成两步：

```
选文件 → 解析 → 预览（新增 X · 覆盖 Y · 保留现有 Z 四类数据）→ 确认 → 写入
```

- **合并不删除**：同 id 用备份版本覆盖，备份里没有的现有记录保留。
- **会提示闸门**：如果备份里候选功能是开启状态，预览里明确写"恢复后会一并开启"。
- 取消不写任何数据（用例覆盖：预览后原记录状态不变）。

### 4.2 清空：分类 + 全清

| 按钮 | 清什么 | 不清什么 |
|---|---|---|
| 清空号码记录 | `tickets` | 核对结果、开奖、批次 |
| 清空核对结果 | `checks` | 号码记录 |
| 清空候选批次 | `candidates` | 已导入的草稿 |
| 清空全部本地数据 | 全部 | — |

`clearCollection()` 有白名单，只允许 `tickets` / `checks` / `candidates`；
传 `draws`、`meta` 会被拒绝（防止误清开奖缓存与闸门配置）。用例锁定。

## 5. 日志脱敏

静态站没有服务端，也没有请求日志，因此**不存在服务端日志泄漏面**。相关事实：

- 导出的备份里 `ownerOpenId` 恒为 `'local'`，不含任何真实身份标识。
- 备份不含 API Key：Key 存在 `localStorage` 的独立键里，`exportAll()` 只读 `meta` 表。
- 全仓扫描 `sk-` 仅命中测试里的假 Key（`tests/web-ai.test.js`）。
- AI 请求不发送身份标识，错误信息不回显 Key（有用例）。

> 早期小程序版的云函数日志脱敏策略仍保留在 `cloudfunctions/`，但已不是主线。
