# 部署到 GitHub Pages（免费，无需服务器）

- 目标：把这个工具变成一个**纯静态网站**，用 GitHub 的免费额度托管 + 定时抓开奖数据。
- 结果：手机/电脑浏览器打开一个网址就能用，不需要服务器、域名、备案、微信审核。
- 适用：个人自用。数据存在你自己的浏览器里。

---

## 0. 为什么能「没有后端」

| 能力 | 实现方式 |
|---|---|
| 页面托管 | GitHub Pages（静态文件，免费） |
| 开奖数据 | GitHub Actions 每天定时抓取官方接口 → 写成 `web/data/draws/*.json` 提交到仓库 → 页面同源读取 |
| 个人号码 / 核对结果 | 浏览器本地存储（IndexedDB，失败自动降级 localStorage） |
| 判奖计算 | 前端复用 `shared/rules/judge.js`（与小程序版同一份代码） |

**关键判断**：官方接口没有 CORS 头，浏览器不能直连。所以把「抓取」放在 GitHub Actions 里跑，产出静态 JSON——Actions 就是那个"免费服务器"。

代价（必须接受）：
- 数据只在当前浏览器，换设备/清缓存会丢 → 用「数据」页导出备份。
- 开奖数据最多滞后一个定时周期（每天 2 次），可手动触发。
- 没有 AI 助手（静态站不能安全存放 API Key）。

## 1. 建仓库并推送

1. 打开 <https://github.com/new>
2. 仓库名随意，例如 `jingcai-assistant`
3. **Visibility 选 Public**（免费账号的 Pages 只支持公开仓库；私有仓库需要付费计划）
4. 不要勾选 README / .gitignore（本地已有）
5. 创建后，在项目目录执行：

```bash
cd D:\codex\号码管理助手
git init
git add .
git commit -m "feat: 静态站版本"
git branch -M main
git remote add origin https://github.com/<你的用户名>/jingcai-assistant.git
git push -u origin main
```

> 仓库里**不能有密钥**。本项目不含任何 key；`.env` 已在 `.gitignore` 里。

## 2. 开启 Pages

1. 仓库页 → **Settings** → 左侧 **Pages**
2. **Build and deployment → Source** 选 **GitHub Actions**（不要选 "Deploy from a branch"）
3. 保存后不用做别的，`deploy-pages` 工作流会在下次 push 时自动跑

推送后去 **Actions** 标签页，应该看到两个工作流：

| 工作流 | 触发 | 作用 |
|---|---|---|
| `deploy-pages` | push / 手动 | 打包前端 + 跑测试 + 发布到 Pages |
| `sync-draws` | 定时（每天 09:00 / 22:00 北京时间）/ 手动 | 抓官方开奖写 JSON 并提交 |

等 `deploy-pages` 变绿，页面地址是：

```
https://<你的用户名>.github.io/jingcai-assistant/
```

## 3. 首次打开

1. 打开上面的网址
2. 页面会自动尝试加载仓库里的开奖 JSON
3. 如果显示「还没有开奖数据」，点 **重新加载开奖**；仍为空就去 Actions 手动跑一次 `sync-draws`

然后就能：录号码 → 确认已购买 → 一键核对 → 看统计。

## 3.5 重要：定时抓取在 GitHub 机器上会被拦（已实测）

GitHub 托管的 Runner 访问中国福彩网，会被**网宿云安全平台按 IP 拦截**：

```
! ssq 同步失败: HTTP 403 网宿云安全平台检测到您当前的访问行为存在异常，请稍后重试
```

加强 UA / Referer / Accept 等请求头**无效**，这是机房 IP 层面的限制，不是请求头问题。
因此：

- `sync-draws` 工作流保留，但标记为「尽力而为」：失败不会让站点变红，也不会清空已有数据。
- **推荐做法：本机一条命令发布**（本机能正常访问福彩网）：

```bash
npm run publish:data                 # 抓 60 期 + 通过 GitHub API 推送到仓库
npm run publish:data -- --count 20   # 只抓 20 期
npm run publish:data -- --dry-run    # 只抓不推
```

它会：本地抓取 → 校验 → 写入 `web/data/draws/*.json` → 用 `gh` 凭据通过 **GitHub API** 提交 → Pages 1–2 分钟内自动重建。

> 为什么走 API 而不是 `git push`：本机实测 `github.com:443` 连接被重置，
> 但 `api.github.com` 正常。脚本因此绕开 git 通道。

想全自动：Windows「任务计划程序」→ 新建任务 → 操作选「启动程序」，
程序填 `npm`，参数填 `run publish:data`，起始位置填项目目录。电脑开机时每天跑一次即可。

## 3.6 AI 助手怎么开

1. 打开站点 → 顶部「AI」页
2. 粘贴自己的 DeepSeek API Key（在 <https://platform.deepseek.com/api_keys> 申请）
3. 点「保存并验证」→ 显示"密钥可用"即可提问

说明：
- Key 只存在**你自己的浏览器**（localStorage），不经过任何服务器，也不在仓库里。
- 费用由你的 DeepSeek 账户承担；单次对话最多 3 轮工具调用、900 tokens。
- 浏览器直连已验证可用（`api.deepseek.com` 会回显 CORS 允许来源）。
- 同一浏览器上的其他脚本理论上能读到 Key：建议用可随时吊销的 Key，不用时点「清除密钥」。

## 3.7 选号（候选组合）怎么用

1. 顶部「选号」页 → 阅读说明 → 勾选（可选：同时允许 AI 调用）→ 点「我已了解，开启」
2. 选彩种、策略、注数，填目标期号 → 点「生成」。策略选「分析选号」时会多出一栏分析权重：
   - 避开连号、等差、同尾扎堆
   - 不含上一期开奖号码
   - 每注至少带几个冷号（0–2）
   - 和值上下限（留空用默认：双色球 75–130，快乐8 300–500）
3. 看结果 → 点「导入为草稿」→ 到「我的号码」逐注确认已购买
4. 开奖同步后回到选号页，展开历史批次可看「该期最高命中 N 个」

三条要知道的：

- **默认关闭**，且开启状态存在你本机浏览器里，**不是服务端强制**（静态站没有服务端）。想彻底停用就点「关闭候选功能」。
- **导入只是草稿**，金额与购买时间都是空，不会自动按 2 元/注填。确认购买时你自己填实际支付金额。
- **同一随机种子 + 同一参数 = 同一批号码**。种子会自动回填，方便开奖后复盘；想换一批就清空种子再生成。

> 生成不读历史频次。历史统计在 AI 页可以问（"近 30 期红球出现最多的是哪几个"），但那只作描述，
> 不会用来加权选号——冷热对独立随机事件没有预测力。

### 「分析选号」到底分析了什么

它不预测号码，而是**避开大众偏好**，降低「万一中的是浮动奖，被很多人平分」的风险：

- 双色球一/二等奖、快乐8 选十中十是**浮动奖，按中奖注数均分**；三等奖及以下是固定奖金，不受影响。
- 每注会显示「拥挤指数」（0–100，越低越冷门）和触发的因子，例如"6 个号都在 1–31"、"3 对连号"、"与上期重号 2 个"。
- 指数是**基于公开研究的推定值**——福彩不公布每注号码的投注分布，所以它不是实测人数。
- 为了低拥挤，号码可能"不好看"（32/33 同出、带连号），页面会把这份代价写出来：平均拥挤、和值范围、几注含大号。

完整依据与权重表：`docs/analysis-model.md`。

想直接让 AI 决定权重，去「AI」页说"按分析的思路给三注，别要生日号，带一个冷门号，和值别太极端"——
它会把这句话翻译成上面那几个参数，号码仍由代码生成（可复现）。

## 4. 日常维护

| 想做什么 | 怎么做 |
|---|---|
| 立刻刷新开奖数据 | 本机执行 `npm run publish:data`（推荐）；或 Actions 手动跑 `sync-draws`（可能被 403） |
| 改代码后发布 | 本地改完 `git push`，Pages 自动重新部署（会自动跑测试，测试挂了不会发布） |
| 换设备 | 旧设备「数据」页导出 JSON → 新设备「恢复备份」 |
| 本地预览 | `npm run build:web && npm run serve:web`，打开 <http://127.0.0.1:5173> |
| 只更新本地数据不推仓库 | `npm run sync:json` |
| 定时全自动更新 | Windows 任务计划每天跑 `npm run publish:data` |

## 5. 常见问题

**Actions 报 `Resource not accessible by integration`**
→ Settings → Actions → General → Workflow permissions → 选 **Read and write permissions** → Save。

**Pages 一直 404**
→ 确认 Source 选的是 **GitHub Actions**；再看 `deploy-pages` 是否成功；首次部署生效通常 1–2 分钟。

**`sync-draws` 失败但页面照常**
→ 脚本设计为：抓取失败时保留已有 JSON 并正常退出，不阻塞站点。偶发网络问题下次定时会补上。

**页面提示"本地数据库不可用"**
→ 无痕/隐私模式会禁用 IndexedDB。代码已自动降级到 localStorage；若两者都被禁用，请用普通窗口打开。

**数据会不会丢**
→ 清浏览器数据、换设备、换浏览器都会丢本地记录。重要数据请定期在「数据」页导出备份（JSON 可读、可恢复）。

**能不能私有仓库**
→ 免费账号的 Pages 不支持私有仓库。若必须私有，两个选择：升级 GitHub Pro，或改用 Cloudflare Pages（免费支持私有仓库，构建命令同样是 `node scripts/build-web.js`，输出目录 `web`）。

**数据更新频率**
→ 仓库里的 `sync-draws` 每天跑 2 次，但受上面 403 限制，实际主要靠 `npm run publish:data`。
建议每天手动或定时跑一次即可，官方站点不需要高频访问。

## 6. 上线前自检（可选但建议）

```bash
npm run build:web        # 打包，产物 web/dist/app.js
node --test tests/*.test.js   # 210 个用例应全绿
npm run sync:json        # 抓一次数据
npm run serve:web        # 本地打开确认能加载
```

## 7. 这个方案的边界

- 不做购彩、代购、兑奖代办；判奖结果仅供核对，兑奖以官方终端与法定机构认定为准。
- 开奖数据来自中国福彩网公开接口，无稳定性承诺；失败时保留旧数据，不会伪造。
- 浮动奖（双色球一/二等奖、快乐8 中 10）金额只读当期公告，缺失就显示「待公告」。
- 旧期（双色球 2026014 前、快乐8 2025350 前）没有规则版本，不自动判奖。
