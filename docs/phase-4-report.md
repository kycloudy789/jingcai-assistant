## 2. 五类"不给结论"的情形（都有测试）

| 情形 | 返回 | 是否落库 |
|---|---|---|
| 未同步开奖 | `pending / NO_DRAW` | 否（D17） |
| 开奖未核验（parsed/conflict） | `pending / DRAW_NOT_VERIFIED` | 否 |
| 期号或彩种不匹配 | `pending / MISMATCH` | 否 |
| 该期无规则版本 | `pending / NO_RULE_VERSION` | 是 |
| 浮动奖未公告（count=0 或缺失） | `pending / PRIZE_AMOUNT_PENDING` | 是 |
| 福运奖状态未知且恰好 3 红 | `pending / FUYUN_STATUS_UNKNOWN` | 是 |

宁可显示"待公告"，也不给一个看起来合理但是编的金额。

用官方当期真实开奖号码构造号码，跑完整判奖链路：

```

仅中 3 红（福运奖边界）    → pending_manual_review  奖级=null 原因=FUYUN_STATUS_UNKNOWN

```
$ node scripts/verify-judge.js kl8
开奖：kl8 2026294 2026-11-04

中 10（浮动奖）  → pending_manual_review  奖级=10  原因=PRIZE_AMOUNT_PENDING

两处"不给结论"正是设计目标：
- 2026126 期福运奖状态 `unknown` → 3 红不给结论，转人工（配置 `fuyunEmptyMeansInactive` 后才可自动判"不中奖"）。
- 2026294 期"10 中 10"当期无人中，官方不公布单注金额 → 显示待公告，不填 0。

## 5. 关键实现点

1. **规则版本按期号解析**，不由开奖记录携带；某期查不到版本 → `NO_RULE_VERSION`，不回退到最新版。
2. **浮动奖不估算**：`announcedGrade()` 在 `count === 0` 时直接返回 `amount: null`——这正好对应快乐8官方"中 10 无人中返回 0/0"的坑。
3. **幂等键** = `ticketId|drawRecordId|ruleVersion|drawHash`。官方更正开奖 → 哈希变 → 生成新核对，`recheckOf` 指旧的，历史可追。
4. **`checkSummary` 只写不读**：任何判定都不读它，只用于列表徽标（D16）。
5. **不改购买状态**：核对后 `purchaseStatus` 仍是 `confirmed`，`checked` 只是结果态（D8）。

## 7. 已知问题

1. 单次核对上限 200 张票，超出需分批（个人使用足够，未做自动分批）。
2. 未做"开奖后自动触发核对"，目前需手动点「一键核对」；自动触发建议放在阶段 7 的定时任务里。
3. 快乐8 的 10 中 10 若当期无人中，永远无法自动出金额（官方本身不公布），只能显示"待公告"——这是规则决定的，不是缺陷。
4. `pending_manual_review` 目前只能"重新核对"或人工判断，没有专门的"人工确认奖金"入口（阶段 7 可加）。
