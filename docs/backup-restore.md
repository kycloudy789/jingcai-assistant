# 备份与恢复说明

> 你的号码、核对结果、候选批次全部只存在**这台设备的浏览器**里。
> 换设备、清缓存、换浏览器配置，都可能丢。所以：**定期导出备份**。

## 1. 备份文件里有什么

| 字段 | 内容 |
|---|---|
| `schema` | `jingcai-web@2`（旧版 `@1` 仍可导入） |
| `exportedAt` | 导出时间 |
| `tickets` | 号码记录（草稿 / 已购买 / 已作废） |
| `checks` | 核对结果（含命中、奖级、金额、幂等键） |
| `draws` | 本地缓存的开奖记录 |
| `candidates` | 候选批次（种子、参数快照、拥挤度摘要） |
| `meta` | 同步时间、闸门状态 |

**不含**：DeepSeek API Key（它在独立的 localStorage 键里，不进备份）。
**含**：`ownerOpenId` 恒为 `'local'`，没有真实身份标识。

## 2. 导出

「数据」页 → **导出备份 JSON** → 文件名 `jingcai-backup-YYYY-MM-DD.json`。

建议时机：

- 换设备前
- 清理浏览器数据前
- 手动录入了一批号码之后
- 升级/改动代码之前（虽然代码升级不会动你的数据，但保险）

## 3. 恢复

1. 「数据」页 → **恢复备份** → 选文件
2. 页面先出**预览**，不写库：
   ```
   号码记录   新增 3 · 覆盖 12 · 保留现有 5
   核对结果   新增 0 · 覆盖 30 · 保留现有 2
   开奖缓存   新增 0 · 覆盖 20 · 保留现有 0
   候选批次   新增 1 · 覆盖 0 · 保留现有 0
   ```
3. 确认无误 → **确认恢复**；或 **取消**（一个字节都不会写）

### 三个必须知道的行为

1. **合并不删除**：同 `id` 用备份里的版本覆盖，备份里没有的现有记录**保留**。
   所以"恢复"不会把你现在多出来的记录弄丢。
2. **开奖缓存也会被覆盖**：如果备份里的开奖数据更旧，恢复后可能退回旧状态。
   恢复完到「开奖」页点一次"从仓库数据重新加载"即可。
3. **闸门状态会跟着回来**：预览里会明确提示"这份备份里候选功能是开启状态，恢复后会一并开启"。
   如果不想开，恢复后到「选号」页点「关闭候选功能」。

## 4. 常见问题

**Q：恢复后号码还在，但中奖情况没了？**
核对结果在 `checks` 里。如果备份里的 `checks` 是空的，恢复后需要重新点「一键核对」。

**Q：能只恢复号码、不动开奖吗？**
目前不支持选择性恢复（预览只做提示，不做勾选）。可以先把当前数据导出，恢复后再挑需要的部分——但更简单的做法是：恢复后在「开奖」页重新加载一次官方数据。

**Q：备份文件能发给别人吗？**
能打开，但**不建议**：里面有你的全部号码记录与购买金额。要分享请先自己删掉 `tickets` / `checks`。

**Q：清空了还能找回吗？**
不能。清空不可撤销。清空前务必先导出。
